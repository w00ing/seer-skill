# Seer v0.7 validation

**Status: validation passed within the measured scope.** Automated checks and native fixture scenarios for capture, Accessibility, regions, semantic waits, and OCR passed. Broader app, macOS, language, and display-scale coverage remains untested; the GitHub release and tag remain unpublished.

Checked on macOS 27.0 (Apple Silicon), Python 3.9.6, Pillow 11.3.0, and Swift 6.4. OCR window-point mapping was measured on a 2× fixture window (520 × 392 points to 1040 × 784 pixels); other display scales remain unverified.

## Completed checks

| Area | Observed result |
|---|---|

| CLI contract | JSON and exit codes, invalid arguments rejected before app queries, source and region forwarding, semantic wait success and query errors. |

## Native fixture validation

```bash
xcrun swiftc tests/manual/window_fixture.swift -o .seer/qa/SeerWindowFixture
python3 tests/manual/verify_v07.py
# Resume OCR without repeating completed Accessibility scenarios:
python3 tests/manual/verify_v07.py --only-ocr --ocr-timeout 30
```

The first integrated fixture run recorded 14 passing scenarios for fresh capture, AX roles/names/values/bounds/enabled states, positive and negative assertions, region filtering, delayed text success, and a valid nonmatch timeout. The fresh screenshot showed the expected labels, buttons, and canvas. Its final OCR inspect returned `query_timeout` with `--timeout 15`, so the report at `.seer/qa/v07-b1ds9dlg/report.json` retains overall status `error`; those 14 cases are not an overall pass for that run.

A later OCR-focused run passed all 10 scenarios in `.seer/qa/v07-gh0ba3fq/report.json`. It covered a fresh capture, full-window OCR, confident text matching, semantic wait, OCR absence returning insufficient evidence unless matching text was detected, text-region mapping, a blank crop, and a closed window ID. Nine command captures were checked against their SHA-256 and requested window ID. The fixture window measured 520 × 392 points and captured as 1040 × 784 pixels (2×); its PNG and the text/blank crops were visually inspected.

The focused run's end-to-end OCR `inspect` took 0.769 seconds, OCR wait 0.791 seconds, text-region crop 0.666 seconds, and blank-region crop 0.634 seconds. The full-window OCR found `Seer Ready`, `Continue`, `Unavailable`, and `Canvas Evidence`, and again misread `Seer QA v0.7` as `Seer QA vO.7`, with confidence 1.0. An earlier Vision-only call on the saved image took 12.994 seconds (recorded in `.seer/qa/v07-b1ds9dlg/ocr-timing.json`); the reason for the timing difference is unconfirmed. Confidence is not a guarantee of exact text. `inspect` and `assert` default to 30 seconds; semantic `wait` remains 10 seconds. A longer explicit budget such as `--timeout 60` is available for slower OCR or cold helper builds.

## Earlier blocked attempts (historical)

The initial live attempt could not capture its window or match it to an Accessibility window. A read-only session check recorded `CGSSessionScreenIsLocked = 1`; the attempt is `.seer/qa/v07-1k114rtf/report.json` and is not counted as a pass. A later preflight returned exit 2 with `blocked_reason: screen_locked` without launching the fixture; its record is `.seer/qa/v07-3omceg71/report.json`. These blocked attempts are historical; they do not describe the current desktop run. No permission or lock setting was changed.

Actual permission denial, a hung real AX server, other macOS/Python versions, other display scales, and third-party app coverage remain untested. Public AX window matching requires a unique title/bounds match. The native helper bounds traversal by node count and depth and reports incomplete evidence; this cannot force an app to expose text it omits. The prior [v0.6 record](v0.6-validation.md) retains its visual fixture results and older doctor timeout limitation.

Inspection reports are saved locally. Assertion/wait verdicts are emitted on stdout and reference those reports; there is no semantic verdict replay command. The GitHub release and tag have not been published.

[Apple's AX timeout API](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout) and [Vision recognition API](https://developer.apple.com/documentation/vision/vnrecognizetextrequest) describe the underlying mechanisms; neither guarantees complete semantic evidence.
