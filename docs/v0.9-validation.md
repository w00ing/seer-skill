# Seer v0.9 validation

This record covers the v0.9 maintenance commands, isolated distribution evaluation, and the native fixture checks described below. No release or tag has been published. Claude Code model-backed tool use remains unverified and is outside the accepted v0.9 completion requirements.

## Automated checks

| Check | Result |
|---|---|
| Python 3.9.6 base environment | 101 tests collected: 92 passed and 9 optional tests skipped in 8.780 seconds. The six MCP and three JSON Schema tests require optional dependencies absent in this environment. |
| Python 3.13.12 with MCP SDK 2.2.0 | All 101 tests passed in 15.795 seconds with ResourceWarnings treated as errors. |
| Existing utilities and packaging | Five Excalidraw tests, all shell syntax checks, relevant ShellCheck, and `claude plugin validate --strict .` passed. |
| Maintenance commands | Ten focused tests cover source-verdict retention, Markdown escaping, verified ZIP contents, tampering, traversal/symlinks, output preservation, bounded FIFO handling, malformed/deep JSON, invalid Unicode, and the export size limit. |
| CLI/MCP parity | The MCP integration test exercises both new commands, help, the retained error verdict, and duplicate-output rejection. |
| JSON contracts | Actual synthetic baseline creation, comparison failure, dimension error, missing baseline, summary/export, and diagnostics validate against the schemas; malformed critical fields are rejected. |

The export reader rejects nonregular files before reading, bounds JSON input to 4 MiB, and caps ZIP evidence at 128 MiB. Final review found and fixed a cyclic output-path error and malformed Unicode handling; their regression cases return JSON errors without publishing output. A real closed-window error from the native fixture was also summarized and inspected: report generation passed while `source_status` remained `error`.

Local logs are `.seer/qa/v09-final-base-unittest.log`, `.seer/qa/v09-final-sdk-unittest.log`, and `.seer/qa/v09-evidence-final.log`. The inspected summary and diagnostic output are `.seer/qa/v09-fixture-error.md` and `.seer/qa/v09-diagnostics.json`. CI runs the checked-in matrix on `macos-26` with Python 3.9 and 3.13; use the [Actions history](https://github.com/w00ing/seer-skill/actions/workflows/smoke.yml) to check a specific commit's result. The CI base row installs JSON Schema support, so only MCP tests are skipped there.

## Isolated installation and repeated verdict evaluation

Both environments staged the archived v0.8 package, exercised first-use baseline behavior, replaced only the temporary installation with the v0.9 candidate, and verified that the approved synthetic baseline remained byte-identical. Each run completed 39 package, update, baseline, and scenario checks. No user installation or host configuration was changed.

| Interpreter / Pillow | Correct verdicts | False passes / expected non-pass cases | Total evaluator time |
|---|---:|---:|---:|
| Python 3.9.6 / Pillow 11.3.0 | 15/15 (100%) | 0/9 (0%) | 2.385 s |
| Python 3.13.12 / Pillow 12.3.0 | 15/15 (100%) | 0/9 (0%) | 2.573 s |

Five synthetic image scenarios were repeated three times: identical pass, change outside a mask, ignored change, dimension mismatch, and missing baseline. Correctness requires both the expected status and exit code; error cases also check their code. False passes count only cases expected to be `fail`, `error`, or `needs_baseline` that instead returned `pass`. These rates describe this finite fixture set and do not estimate arbitrary-app reliability. Total time includes local staging, package checks, and comparisons, ending before the final report files are written; individual command times are retained in JSON.

## Native fixture

The existing `tests/manual/verify_v08.py` runner was reused against the v0.9 candidate on macOS 27.0, Apple Silicon, Python 3.13.12, Pillow 12.3.0, and MCP SDK 2.2.0. It controls only `SeerWindowFixture` and exercises an actual stdio MCP connection.

All seven expected outcomes matched: window discovery, exact-window capture, AX text match, text mismatch, semantic wait, missing baseline, and closed-window error. There were **0 false passes among 3 expected non-pass cases**. This is a small deterministic fixture sample, not an estimate of arbitrary-app reliability.

| Operation | Observed seconds |
|---|---:|
| Window discovery | 4.176 |
| Exact fixture capture | 0.435 |
| AX text match | 1.226 |
| AX mismatch | 0.285 |
| Semantic wait | 0.280 |
| Missing baseline | 0.109 |
| Closed-window error | 0.209 |

The seven calls totaled 6.720 seconds; fixture startup and MCP setup are excluded. The fresh 1040 × 784 PNG was inspected directly: it shows “Seer Ready,” enabled “Continue,” disabled “Unavailable,” and the canvas text. The runner verified the capture SHA-256. The fixture uses the same 2× geometry measured in v0.7; other display scales were not exercised. No real baseline was created and no user app content or macOS privacy settings were changed.

Local evidence is `.seer/qa/v08-native-83tei4sj/report.json`, its adjacent capture directory, and `.seer/qa/v09-native-run.log`. The v0.8 prefix reflects the reused runner, not the candidate version. Reproduce with:

```bash
mkdir -p .seer/qa
xcrun swiftc tests/manual/window_fixture.swift -o .seer/qa/SeerWindowFixture
# Activate an isolated environment containing requirements-mcp.txt first.
python tests/manual/verify_v08.py
```

## Limits

The native fixture does not establish behavior across all macOS releases, third-party apps, Intel Macs, display scales, or permission configurations. Actual permission denial and a hung real AX server remain untested. OCR's earlier v0.7 measurements and limitations remain in [that validation record](v0.7-validation.md); v0.9 does not claim a new OCR evaluation.

The [distribution check](distribution-check.md) describes the local-copy installation boundary. It does not establish a successful marketplace download or authenticated Claude model use. The [compatibility matrix](compatibility.md) separates native measurements from automated CI coverage. See [evidence management](evidence-management.md) and [JSON contracts](json-contract.md) for what summaries, exports, and schema checks do and do not prove.
