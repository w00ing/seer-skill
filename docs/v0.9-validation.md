# Seer v0.9 validation

This record covers the v0.9 maintenance commands, isolated distribution evaluation, native fixture checks, and the subsequent Claude Code host evaluation described below. No release or tag has been published. The Claude task passed after authenticated access became available; it had been an explicitly deferred validation gap at v0.9 completion.

## Automated checks

| Check | Result |
|---|---|
| Python 3.9.6 base environment | 101 tests collected: 92 passed and 9 optional tests skipped in 8.780 seconds. The six MCP and three JSON Schema tests require optional dependencies absent in this environment. |
| Python 3.13.12 with MCP SDK 2.2.0 | All 101 tests passed in 15.795 seconds with ResourceWarnings treated as errors. |
| Existing utilities and packaging | Five Excalidraw tests, all shell syntax checks, relevant ShellCheck, and `claude plugin validate --strict .` passed. |
| Maintenance commands | Ten focused tests cover source-verdict retention, Markdown escaping, verified ZIP contents, tampering, traversal/symlinks, output preservation, bounded FIFO handling, malformed/deep JSON, invalid Unicode, and the export size limit. |
| CLI/MCP parity | The MCP integration test exercises both new commands, help, the retained error verdict, and duplicate-output rejection. |
| JSON contracts | Actual synthetic baseline creation, comparison failure, dimension error, missing baseline, summary/export, and diagnostics validate against the schemas; malformed critical fields are rejected. |

The export reader rejects nonregular files before reading, bounds JSON input to 4 MiB, and caps ZIP evidence at 128 MiB. Final review found and fixed a cyclic output-path error and malformed Unicode handling; their regression cases return JSON errors without publishing output. A real closed-window error from the native fixture was also summarized and inspected: report generation passed while `source_status` remained `error`.

Local logs are `.seer/qa/v09-final-base-unittest.log`, `.seer/qa/v09-final-sdk-unittest.log`, and `.seer/qa/v09-evidence-final.log`. The inspected summary and diagnostic output are `.seer/qa/v09-fixture-error.md` and `.seer/qa/v09-diagnostics.json`. CI runs the checked-in matrix on `macos-26` with Python 3.9 and 3.13; use the [Actions history](https://github.com/w00ing/seer-skill/actions/workflows/smoke.yml) to check a specific commit's result. ## Native fixture

The existing `tests/manual/verify_v08.py` runner was reused against the v0.9 candidate on macOS 27.0, Apple Silicon, Python 3.13.12, Pillow 12.3.0, and MCP SDK 2.2.0. It controls only `SeerWindowFixture` and exercises an actual stdio MCP connection.

Local evidence is `.seer/qa/v08-native-83tei4sj/report.json`, its adjacent capture directory, and `.seer/qa/v09-native-run.log`. The v0.8 prefix reflects the reused runner, not the candidate version. Reproduce with:

## Claude Code host follow-up

On 2026-09-26, Claude Code 2.1.283 completed the representative MCP task against Seer 0.9.0 at commit `a0fb034815c25da9309cb9cdba0af1d46f0ade7d`. Its event log reports model identifier `claude-opus-5-5`. The adapter used the existing isolated Python 3.13.12 / Pillow 12.3.0 / MCP SDK 2.2.0 environment on macOS 27.0, Apple Silicon. This is a new measured result; the [v0.8 authentication failure](v0.8-validation.md#host-workflow-evaluation) remains historical evidence.

The host used temporary MCP configuration, an explicit isolated project root, no saved session, no loaded settings sources, and only the two Seer tools. The project contained synthetic 16 × 16 images and one prepared synthetic baseline. No saved host configuration, user installation, real baseline, or app content was changed.

| Requested call | Observed result |
|---|---|
| `seer_help` with `command: "verify"` | Returned CLI usage before the comparisons. |
| `seer_run` with `["verify", "ready.png", "fixture"]` | `pass`; 0/256 pixels changed; `baseline_updated: false`. |
| `seer_run` with `["verify", "changed.png", "fixture"]` | `fail`; 256/256 pixels changed; `baseline_updated: false`. |
| `seer_run` with `["verify", "ready.png", "missing"]` | `needs_baseline`; returned approval guidance and left the missing baseline absent. |

The actual tool event log contains exactly these four calls, with no permission denials or delegated agents. Claude's final answer correctly described all three verdicts and baseline preservation. Independent filesystem checks confirmed the original baseline SHA-256 remained `7c002f793d45e63b8f839a95724a738ec56f14358f2e7f6e77de4a73d94b954c`, and the baseline directory still contained only `fixture.png`. Both comparison results agreed with their saved reports; all eight manifest-declared files passed size and SHA-256 checks.

The task produced **3/3 expected verdicts and 0/2 false passes** in one run. The whole Claude subprocess took **10.376 seconds**, including startup, MCP setup, model requests, and tool calls. This finite synthetic task does not measure arbitrary-app reliability or Claude-driven native window capture, OCR, waits, or maintenance commands. The marketplace installer was not exercised.

Local evidence remains under `.seer/qa/claude-host-v09-k3aoq448/`: `report.json` contains the checked assertions, `claude.stdout.jsonl` contains actual tool events, and `.seer/loop/runs/` contains the two comparison bundles. The local harness is `.seer/qa/verify-claude-v09.py`; no raw host logs or images are committed.

To repeat the host portion, prepare an isolated synthetic fixture with matching `ready.png` / baseline `fixture`, changed `changed.png`, and no baseline named `missing`. Use the [temporary MCP configuration](mcp-integration.md#claude-code-temporary-json-configuration), pointing `--project-root` at that fixture directory. This run used a 60-second adapter command timeout and a 120,000 ms host tool timeout. Run from the fixture directory:

```bash
MCP_TIMEOUT=20000 claude -p --strict-mcp-config --mcp-config "$MCP_CONFIG" \
  --no-session-persistence --tools "" \
  --allowedTools mcp__seer__seer_help mcp__seer__seer_run \
  --permission-mode dontAsk --setting-sources "" \
  --output-format stream-json --verbose --max-budget-usd 2 \
  'Evaluate only the configured Seer MCP server using its seer_help and seer_run tools. Do not use shell, other tools, or delegate. First call seer_help with command verify. Then call seer_run exactly for each arguments array: ["verify","ready.png","fixture"], ["verify","changed.png","fixture"], ["verify","ready.png","missing"]. Report the three status strings and whether the missing baseline was created. Do not create or replace any baseline.'
```

Inspect tool events and saved reports, and compare baseline hashes before and after the run; a successful host exit alone is insufficient evidence.

## Limits

The native fixture does not establish behavior across all macOS releases, third-party apps, Intel Macs, display scales, or permission configurations. Actual permission denial and a hung real AX server remain untested. OCR's earlier v0.7 measurements and limitations remain in [that validation record](v0.7-validation.md); v0.9 does not claim a new OCR evaluation.

The [distribution check](distribution-check.md) describes the local-copy installation boundary and does not establish a successful marketplace download. Authenticated Claude model use was measured separately in the bounded task above. The [compatibility matrix](compatibility.md) separates native measurements from automated CI coverage. See [evidence management](evidence-management.md) and [JSON contracts](json-contract.md) for what summaries, exports, and schema checks do and do not prove.
