# Seer 0.6.0 — pending publication

**Publication status:** pending. This note prepares local release documentation; it does not announce a GitHub release or tag.

Seer 0.6.0 adds stable-frame capture, explicit dynamic-region masks, capture metadata, and reproducible per-comparison evidence.

- `wait --stable` captures one exact native window ID until frames meet a pixel-difference threshold over a stable interval. It compares against an interval anchor, resets the interval after a change, and requires at least two frames. Timeout covers the capture subprocess, returns `fail` with reason `timeout`, and does not publish or replace `--out`; operational capture and input errors return `error`.
- `verify` and `wait` accept repeated `--ignore-rect X,Y,WIDTH,HEIGHT` options. Rectangles use baseline PNG pixels and half-open bounds, must be fully in bounds, and are strictly validated. Overlapping exclusions count once; ignored pixels leave both the changed-pixel numerator and denominator. Invalid rectangles and full-image exclusion are errors.
- Comparison reports PNG dimension and known DPI mismatches. Resizing is never implicit; `verify --resize` explicitly opts into the baseline pixel grid, and `scale_evidence` records that choice. A pixel-dimension mismatch without the flag returns `image_size_mismatch`; with matching dimensions, a known DPI mismatch without the flag returns `image_scale_mismatch`. Unknown scale is not reported as verified.
- Captures receive a hash-bound `.seer.json` sidecar with available capture time, window ID, image dimensions, and DPI metadata. Its path appears as `artifacts.metadata`. Missing or stale external metadata is left unknown rather than inferred.
- Each comparison with a valid baseline/current image preserves the baseline snapshot, current image, report, manifest, comparison options, relative artifact paths, and checksums in a unique immutable bundle under `.seer/loop/runs/`. A diff is present when pixel comparison succeeds; dimension or scale mismatch attempts preserve the snapshots and report without a diff. Missing baselines and invalid inputs rejected before comparison setup leave the loop directory untouched. This preserves the comparison evidence when an explicitly approved baseline update changes the active baseline.

Visual pass results describe pixel similarity or the measured stable-frame condition. They do not assert semantic UI correctness. Existing explicit baseline approval requirements remain: missing baselines are reported without creating them, and baseline creation or replacement requires approval.

Compatibility changes: known DPI mismatches now return `image_scale_mismatch` unless the caller explicitly opts into normalization with `--resize`. CLI consumers should handle the new comparison error codes and the `wait` command's `pass`, `fail` (including timeout reason), and `error` results. Successful `wait` JSON reports `reason: "stable"`, its effective `condition`, final capture metadata in `capture`, and image and sidecar paths in `artifacts`. Capture now emits a `.seer.json` metadata sidecar; tools that copy or modify captures independently must keep the sidecar hash association in mind.

Validation: 46 automated tests, 5 Excalidraw regressions, shell syntax/ShellCheck, strict plugin validation, and 6 real-window scenarios passed. The older lifecycle verifier timed out in its unchanged doctor probe; actual permission-denial tests and broader platform coverage remain unverified. See [v0.6 validation](../v0.6-validation.md) for evidence and limits.
