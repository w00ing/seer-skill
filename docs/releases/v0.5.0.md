# Seer 0.5.0 — pending publication

**Publication status:** pending. This note prepares local release documentation; it does not announce a GitHub release.

Seer 0.5.0 strengthens the native-window capture and error-reporting path for coding-agent visual checks.

- Capture can target a specific session-scoped macOS `window_id`; the ID continues to refer to that window through moves and reordering and becomes invalid when the window closes or is recreated. Process-based capture remains available as a compatibility path.
- Capture writes to a fresh temporary image, validates PNG format and image data with Pillow in the active `python3` environment, and atomically replaces the requested output only after validation. Failed capture or validation preserves an existing output file.
- Exact-ID capture checks on-screen window membership before and after capture, rejecting cached pixels that macOS can still return after a window closes.
- Operational CLI failures now share the versioned JSON error schema (`schema_version: 1`, `operation`, `status: "error"`, and `error: {code, message}`), return exit 2, and keep human-readable diagnostics on stderr. `--help` remains plain text. Stable codes cover invalid arguments, unsupported platforms, missing dependencies, subprocess errors, invalid subprocess output, Accessibility requirements, filesystem errors, and not-ready state.
- `doctor` reports `frontmost_process` separately from the visible-window Accessibility probe under `capabilities.window_query.authorized`; an unsuccessful probe alone does not distinguish denied access from having no accessible visible window.
- macOS CI runs the dependency-free Excalidraw regression script after smoke tests.

Visual verification still requires an explicitly approved baseline. A missing baseline returns `needs_baseline` (exit 3) and is never silently created. Comparison masks, stable-frame detection, and an MCP interface are future work and are not included in 0.5.0.

Compatibility changes: capture now requires Pillow in the active `python3` environment. CLI consumers that previously expected empty stdout on exit 2 must now parse the JSON error object. Lower-level shell scripts retain their stderr diagnostic and empty-stdout error behavior.

Validation: 24 automated tests, 5 Excalidraw regressions, shell syntax/ShellCheck, plugin validation, and 7 real-window scenarios passed locally. Actual permission-denial testing remains separate from simulated failures. See [v0.5 validation](../v0.5-validation.md) for the evidence and remaining gaps.
